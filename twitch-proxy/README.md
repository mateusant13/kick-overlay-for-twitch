# KO Twitch proxy (HD, no SSAI ads)

The Twitch player fetches its HLS master/media playlists from a few hosts. Twitch
stitches SSAI ads into those playlists **at the edge**, based on the **egress
IP/region** of the request. A proxy located in a region where Twitch does not
fill ads returns a **clean HD playlist**; the browser then downloads the video
segments directly (not through the proxy), so the proxy only carries a few MB of
playlist/usher/GQL traffic per session.

This is the same idea as TTV LOL PRO. It does **not** modify the native Twitch
player and it does **not** replace the `<video>` element, so seek, fullscreen,
quality, and controls stay exactly as Twitch ships them.

## What the extension routes through the proxy

```
usher.ttvnw.net
gql.twitch.tv
*.playlist.ttvnw.net
*.playlist.live-video.net
```

Video segments (`video-weaver.*.hls.ttvnw.net`) stay direct. If a specific
region still shows ads, enable "proxy all" in the extension later (not exposed
yet) or use a different VPS region.

## Requirements

- A cheap Linux VPS (Ubuntu 22.04/24.04, 512 MB RAM is plenty) in a region where
  Twitch does not serve SSAI ads. TTV LOL PRO uses Russia; any region with no ad
  fill works. **A proxy on your own machine does not help** — its egress is your
  own ad-eligible IP.
- Port `8899/tcp` reachable from your browser (or adjust `KO_PROXY_PORT`).
- Node.js >= 18 (the installer installs 22).

Already have an HTTP proxy (a VPS, a TTV LOL PRO proxy, a work proxy)? Skip the
server section: enter its `host:port` + credentials directly in the extension
popup. The proxy must allow `CONNECT` to the Twitch hosts listed above.

## Install (on the VPS)

Copy this `twitch-proxy/` folder to the VPS and run:

```bash
sudo bash install.sh
```

The script installs Node, creates a `nobody` systemd service, generates a random
basic-auth password, opens the port in `ufw` when active, and prints:

```
Address : 203.0.113.10:8899
Auth    : ko:xxxxxxxxxxxxxxxxxxxxxxxx
```

Check it:

```bash
curl http://203.0.113.10:8899/health
curl -x http://ko:PASS@203.0.113.10:8899 -s https://ipinfo.io/country
```

`ipinfo.io/country` must be the VPS country (not your home country). Twitch's
ad decision is tied to that egress.

## Configure the extension

Open the extension popup on any page:

1. Tick **Proxy HD (sem ads)**.
2. Fill `host:port` with the address printed by the installer (`203.0.113.10:8899`).
3. Fill user/pass with the generated credentials.
4. Click **Save proxy**.
5. Reload the Twitch tab once.

The popup applies a PAC script that proxies only the four Twitch hosts above and
returns `DIRECT` for everything else. Turning the checkbox off clears the PAC.

## Verify

- Reload the Twitch stream. The player must stay native: no `#ko-adfix`, no
  hls.js iframe, normal Twitch controls, 1080p.
- During an ad break, the playlist should remain clean. The extension's
  `window.__koTwitchAdblockStats.workerPlaylistLog` should show `adExtinf: 0`.
- If you see "Commercial break in progress", the proxy IP/ASN is flagged; move
  the VPS to another provider/region.

## Security

- Basic auth is generated by the installer. Do not run this proxy without auth
  on a public IP: an open CONNECT proxy can be abused.
- The proxy only tunnels TLS; it cannot read Twitch credentials or video
  content. It sees destination hostnames.
- To restrict further, set `KO_PROXY_ALLOW` to your home IP and firewall the port
  to that IP:
  ```bash
  ufw allow from YOUR.IP to any port 8899 proto tcp
  ufw delete allow 8899/tcp
  ```

### SSH tunnel (no exposed port)

If you do not want the proxy port public, install it loopback-only:

```bash
sudo KO_PROXY_HOST=127.0.0.1 bash install.sh
```

Then keep a tunnel open from your PC:

```bash
ssh -N -L 8899:127.0.0.1:8899 user@your-vps
```

In the extension popup use `host:port = 127.0.0.1:8899` with the same
user/pass. The SSH tunnel carries the Playlist/Auth traffic encrypted; nothing
is exposed on the VPS public interface.

## Manual run (development)

```bash
KO_PROXY_PORT=8899 KO_PROXY_AUTH=ko:dev node ko-proxy.mjs
```

Then set the extension proxy to `127.0.0.1:8899` / `ko` / `dev`. This proves the
routing, but a local egress is your own IP, so it will not remove ads.

## Why not strip playlists client-side?

That was the 0.8.15–0.8.17 path. It works for mixed playlists but not for an
all-ad playlist: there is no content in the response to serve, so the client
must either freeze, replay the last frame, or swap in a 360p source. All three
were rejected. The proxy avoids the ad at the source, in HD, with no player
change.
